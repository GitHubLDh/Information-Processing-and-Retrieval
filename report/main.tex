\begin{abstract}
Existing movie search tools let users filter by title, genre, cast, or year, but fail
when a user remembers only a vague plot detail rather than any exact metadata. We
combine two linked sources: \textit{The Movie Database (TMDB) Comprehensive Dataset}
(Kaggle, by rishabhkumar2003), containing structured movie metadata including cast,
genres, ratings, and release info, and plot summaries scraped from Wikipedia via an
API. Linking the two by title and year produces a collection where each movie has both
structured, filterable metadata and a free-text narrative description, enabling
retrieval that goes beyond exact fields to find movies by what a user actually
remembers about them. This report covers the data sources, the collection and linking
pipeline, dataset characterization, and a set of prospective information needs
motivating the retrieval work in later milestones.
\end{abstract}

\section{Topic}
% The differentiating angle: why movies despite it being a common topic.
Movies are a common dataset choice, so the retrieval goal deliberately does not center
on metadata search (genre, year, cast) that any catalog already supports well. Instead,
the goal is retrieval driven by \emph{what a user remembers about a movie} — a plot
detail, a theme, a narrative trope, or what critics said about it — rather than what
they can already filter for. This motivates linking structured TMDB metadata with two
free-text sources: Wikipedia plot summaries (narrative content) and TMDB user reviews
(reception and opinion), so that information needs can be phrased the way people
actually half-remember movies, not the way a database schema represents them. For
example: \textit{``A story where the main character can't trust their own memories or
perception of reality, and slowly uncovers a hidden truth about who they really
are.''} No metadata field captures this, and no single keyword match is reliable
either — it requires matching the collection's free text to a vaguely-recalled theme.

\section{Data Sources}

\subsection{The Movie Database (TMDB) Comprehensive Dataset}
Kaggle dataset by rishabhkumar2003~\cite{tmdb-kaggle}, sourced from the TMDB API. Five CSV files:
\texttt{movies.csv} (9{,}771 rows — one per movie; title, overview, release date,
runtime, budget, revenue, rating, vote count, genres, language), \texttt{cast.csv}
(\textasciitilde150{,}000 rows), \texttt{crew.csv} (\textasciitilde63{,}600 rows),
\texttt{genres.csv} (a 20-row reference table, not a per-movie join table — genres are
already embedded in \texttt{movies.csv}), and \texttt{reviews.csv} (user reviews,
13{,}073 rows after parsing). No IMDb ID field exists in this dataset. The dataset is
licensed CC~BY-NC-SA~4.0 — non-commercial use with attribution and share-alike, which
is compatible with this (non-commercial, academic) project.

\paragraph{Authority assessment.} The dataset is published by a third-party Kaggle
contributor (rishabhkumar2003), not by TMDB itself, but its acquisition method is
documented (the official TMDB API) and the underlying source, TMDB, is a
long-established, actively moderated community movie database used by numerous
production applications (e.g.\ Plex, Kodi), which lends indirect authority. Per-row
\texttt{created\_at}/\texttt{updated\_at} timestamps indicate a recent snapshot
(February 2026). During cleaning we spot-checked several well-known entries (e.g.\
\textit{Interstellar}, \textit{Star Wars}) and found their metadata plausible and
accurate.

\subsection{Wikipedia}
Plot summaries for each movie, retrieved via the Wikipedia and MediaWiki API's
\texttt{action=parse} endpoint~\cite{wikipedia,mediawiki-api}, linked to TMDB IDs
through Wikidata~\cite{wikidata} using property P4947, rather than by title matching,
to avoid collisions with same-titled non-film articles. Wikipedia text is licensed
CC~BY-SA~4.0.
% TODO: confirm exact license wording to cite.

\paragraph{Authority assessment.} Wikipedia's authority is crowd-sourced rather than
centrally verified: article quality depends on how actively a given page is edited and
cited. High-profile films tend to have well-maintained, citation-backed articles, while
niche titles may have thin or stale ones — a disparity already visible in our linking
results, where mainstream genres (e.g.\ Adventure, Action) link to an English Wikipedia
article far more often than niche categories (e.g.\ Documentary, TV Movie).

\section{Collection \& Preparation}
The collection pipeline has four stages, run by different group members and merged
into a single final collection:
\begin{enumerate}
  \item \textbf{Movies/reviews cleaning} — deduplicate movies, drop movies with no
    release date, clean review text (strip HTML/Markdown formatting), drop empty or
    very short (\textless20 words) reviews, drop duplicate reviews. Result:
    9{,}771 $\rightarrow$ 9{,}710 movies, 13{,}073 $\rightarrow$ 12{,}248 reviews.
  \item \textbf{Wikidata linking} — resolve each TMDB ID to an English Wikipedia
    article title via Wikidata property P4947. 7{,}016 / 9{,}710 movies (72.3\%)
    linked successfully.
  \item \textbf{Wikipedia fetching \& parsing} — fetch each linked article and extract
    its Plot section. 74 of the 7{,}016 linked articles parsed so far.
    % TODO: numbers once the fetch runs on the full linked set with the corrected titles.
  \item \textbf{Final join} — aggregate cast/crew to one row per movie, then
    merge cleaned movies, reviews, Wikidata links, and Wikipedia plots into one
    JSONL document per movie, validated line-by-line against our JSON Schema. 74
    documents so far; the count tracks step~3's output and grows as parsing completes.
\end{enumerate}
The final join also emits a manifest (\texttt{collection\_manifest.json}) recording
source row counts, applied filters, and the git commit under which the run happened,
so the build is reproducible from a clean checkout. Figure~\ref{fig:dfd} shows the
data flow; note that the cast/crew CSV files enter through a separate aggregation
step (4a) that emits one row per movie, so the join never duplicates a movie.

\subsection{Reviews}
Of 9{,}710 cleaned movies, 6{,}013 (62\%) have zero reviews after cleaning; review
coverage is sparse and concentrated on popular titles. Movies with at least one review
average 1.26 reviews (median 0 across all movies, since most have none); reviews
average 239 words (median 181), with a right-skewed distribution
(Figure~\ref{fig:review-length-hist}). Review length shows essentially no correlation
with a movie's rating (Pearson $r = 0.115$, $n=3{,}697$), visible as a dense, largely
flat scatter in Figure~\ref{fig:review-length-rating}. The most frequent words across
all reviews, after stopword removal, are dominated by generic film-review vocabulary
(\textit{story, character, cast, plot, scenes}) rather than genre-distinctive terms —
see \texttt{data/interim/movies\_reviews\_report.md} for full tables.

\subsection{Final collection (74 documents so far)}
The joined collection currently holds 74 documents (one per parsed plot); the numbers
below are for this partial set and will be regenerated by
\texttt{scripts/collection\_stats.py} once step~3 completes. Every document carries a
full Wikipedia plot (496--920 words), a \texttt{wikipedia} object with Wikidata and
IMDb ids, the capped 20-entry cast, crew names plus display-only roles, and at least
one review (814 reviews in total, up to 53 per movie). Genre coverage is led by
Adventure (49), Action (40), Science Fiction (30) and Drama (21); 62 of 74 movies
come from the 2000s/2010s. Plots and reviews together supply a vocabulary of
$\sim$17{,}144 unique terms; plot text is dominated by proper nouns (``Stark'',
``Harry'', ``Joker''), while review text stays in generic film-review vocabulary
(``story'', ``character'', ``time'') — matching the reviews-only characterization
above. Integration discipline holds throughout: every missing value is \texttt{null}
(no sentinels), five movies have multiple directors, and none lack cast or crew.

rather than metadata filters, since the latter is already well-served by existing
movie catalogs.

  \item A movie whose reviewers describe the comedy as clever, witty, or
    intellectually sharp, rather than slapstick or lowbrow.
  \item A romantic movie where reviewers are divided — some call it predictable or
    clichéd, others find it genuinely heartwarming.
  \item A science-fiction survival film about astronauts stranded away from Earth who
